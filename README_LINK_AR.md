# MarPatients Admin — تجهيز ربط المجمعات (V1)

هذا **تحديث لمستودع MarshalAdmin-app**، وليس مشروع Flutter جديدًا. ارفع الملفات بمساراتها كما هي واستبدل المتطابق منها.

## ماذا أضفنا؟
- شاشة الإدارة تستخدم **تسجيل دخول مالك عبر السيرفر** عندما يتم تحديد `MAR_API_URL`.
- إضافة/تعديل العملاء، وإظهار/إخفاء المجمع، وتفعيل/إيقاف الخدمة عبر API.
- خدمة `api/` تحتفظ بجدول العملاء وتبدأ بـ266 عميلًا من قائمتك، **كلهم مخفيون وغير مفعّلين**.
- تطبيق الإدارة وحده يستطيع التعديل بعد التحقق على السيرفر. تطبيق المرضى يقرأ القائمة العامة فقط.
- لا توجد بيانات مرضى أو كلمات مرور Oracle في الخدمة.

## مهم قبل رفع الملفات
- ارفع محتويات هذا الملف المضغوط إلى **مستودع الإدارة**، وليس مستودع المرضى.
- مسار GitHub Actions يجب أن يكون **`.github/workflows/build-admin-apk.yml`**، وليس `github/workflows`.
- **لا تضع كلمة مرور أو مفتاح API داخل GitHub أو الكود.**

## كيف نُفعّل الربط الفعلي لاحقًا؟
1. ننشر مجلد `api/` على خدمة HTTPS مع قاعدة PostgreSQL دائمة ونسخ احتياطي.
2. نضيف أسرار الخدمة في إعدادات الاستضافة (لا في GitHub): `OWNER_USERNAME` و`OWNER_PASSWORD` جديدة وفريدة (12 حرفًا على الأقل) و`TOKEN_SECRET` عشوائي قوي (32 حرفًا على الأقل) و`DATABASE_URL`.
3. نضيف متغير GitHub Actions باسم `MAR_API_URL` في **مستودع الإدارة**، وقيمته عنوان HTTPS الخاص بخدمة API، مثل `https://your-service.example` (مثال فقط، ليس عنوانًا شغالًا).
4. نبني APK جديدًا من Actions. وقتها حساب المدير يُتحقق منه على السيرفر.
5. نضع **نفس العنوان** في مستودع المرضى ونبني تطبيق المرضى.

**إذا لم يتم ضبط `MAR_API_URL`، سيعمل تطبيق الإدارة بوضع التجربة المحلية كما كان، والتعديلات لن تصل للمرضى.**

## حدود النسخة
- API المجمعات جاهز برمجيًا واختُبرت عمليات تسجيل الدخول والإضافة والتفعيل/الإخفاء محليًا؛ لم يُنشر بعد.
- لا يوجد اتصال Oracle أو SMS OTP أو بيانات أطباء/حجوزات حقيقية بعد.
- قبل التشغيل الإنتاجي يلزم MFA لحساب المالك، وتحديد محاولات الدخول على مستوى البنية التحتية، ومراقبة وأمان ونسخ احتياطي لقاعدة البيانات، ومراجعة أمان مستقلة.
- لا تعتمد على SQLite على استضافة ذات ملفات مؤقتة؛ استخدم PostgreSQL دائمة.
